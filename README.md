# VPe03 — GitHub Actions → Docker → Beget

Вариант 2 задания: учебный проект и автодеплой через GitHub Actions вместо Coolify.
Python использует только стандартную библиотеку. `/` — страница, `/health` — JSON с версией и SHA коммита, неизвестные пути возвращают 404.

## Как работает обновление

1. `git push origin main` запускает `.github/workflows/deploy.yml`.
2. GitHub runner собирает образ `vpe03-demo:<SHA>` и проверяет HTTP-ответы.
3. Образ передаётся потоком `docker save | gzip | ssh` на VPS. На VPS сборки нет.
4. `/opt/vpe03-demo/deploy.sh` заменяет только контейнер `vpe03-demo` и проверяет SHA в `/health`.
5. При неудачной проверке запускается предыдущий образ. Сохраняются текущий и предыдущий образы проекта.

Обновление сопровождается коротким перерывом доступности именно учебного приложения.
Данные пользователей не хранятся. Это демонстрационный HTTP-сервис, без авторизации и HTTPS.

## Первоначальная настройка

Нужны существующие Docker Engine, SSH, bash, gzip, flock, curl и Python 3 на Linux VPS; на локальном компьютере — Git и gh с авторизацией.

- Создать репозиторий и загрузить этот проект.
- Под администратором создать `/opt/vpe03-demo` с правами 700 и поместить туда `deploy/deploy.sh`, также с правами 700.
- Сгенерировать отдельный ключ Ed25519 для этого проекта.
- В `/root/.ssh/authorized_keys` добавить публичный ключ с префиксом:
  `restrict,command="/opt/vpe03-demo/deploy.sh" ssh-ed25519 ...`
- Создать GitHub Actions secrets: `DEPLOY_KEY` — отдельный приватный ключ, `VPS_HOST` — адрес сервера, `KNOWN_HOSTS` — проверенный ключ SSH сервера. Ключ сервера получить через уже доверенное административное подключение; не отключать StrictHostKeyChecking.
- Проверить, что TCP-порт 18083 свободен и доступен извне, затем отправить `main` на GitHub.

Ключ CI не разрешает интерактивную оболочку и перенаправления. Однако он позволяет доставлять исполняемый Docker-образ: доступ на запись в main и изменение Actions secrets должны иметь только доверенные администраторы. Основной административный SSH-ключ в GitHub не передаётся.

## Изоляция и ресурсы

Контейнер слушает отдельный порт `18083`, не использует host network, Docker socket или каталоги хоста. Запускается от UID 65534 с read-only filesystem, без Linux capabilities, с `no-new-privileges`, лимитами 96 MiB RAM / 0.25 CPU / 32 PID. Логи ограничены 2 × 2 MiB. Политика перезапуска — `unless-stopped`.

Существующие Nginx, Vaultwarden и SSH-туннели не перенастраиваются. Общая очистка Docker (`system prune`) не используется.

## Проверка

```sh
curl -fsS http://SERVER_IP:18083/health
ssh root@SERVER_IP 'docker ps --filter name=^/vpe03-demo$'
gh run list --repo vtaranov/zerocoder-vpe03-vps
```

Значение `commit` должно совпадать с SHA успешного workflow.

## Восстановление

- После перезапуска Docker контейнер запускается автоматически, если его не остановили вручную.
- Для повторного деплоя текущего кода: Actions → Build and deploy to Beget → Run workflow.
- Для отката к старому коду: сделать `git revert` нужного коммита и отправить main; Actions соберёт и установит восстановленную версию.
- При потере VPS: подготовить Docker и SSH на новом сервере, повторить первоначальную настройку, обновить VPS_HOST и KNOWN_HOSTS, запустить workflow. Приложение не имеет постоянных данных.
- При потере/компрометации CI-ключа: удалить только строку `vpe03-github-actions` из authorized_keys, создать новую пару, заменить DEPLOY_KEY и соответствующую публичную строку. Не трогать другие ключи.
- Логи: `docker logs --tail 100 vpe03-demo`; состояние: `docker inspect vpe03-demo`.

Исходники и сценарий деплоя хранятся в Git. GitHub secrets не входят в резервную копию репозитория; при восстановлении ключ можно перевыпустить.
